# 数值规则表——数值策划补齐版

> 目标：在不推翻现有角色性格和行为倾向的前提下，补齐可直接实现的数值规则。\
> 核心体验目标：两只桌宠有稳定可感知的性格差异；状态会影响行为，但不因随机和数值极端导致“抽风”；玩家不能通过短时间重复交互快速刷满关系。

---

## 1. 最终行为权重规则

原表中“基础权重 = 10”和行为表“基础概率 0.05~0.30”存在冲突。

### 最终方案

保留行为表原本的相对倾向，将“基础概率”改名为“基础权重”，统一乘 100：

| 原值 | BaseWeight |
|---:|---:|
| 0.05 | 5 |
| 0.10 | 10 |
| 0.15 | 15 |
| 0.20 | 20 |
| 0.30 | 30 |

最终公式：

```text
FinalWeight
= BaseWeight
× PersonalityMultiplier
× EnergyMultiplier
× MoodMultiplier
× RepeatMultiplier
```

最后对所有合法候选行为的 `FinalWeight` 做归一化并加权随机。

> `BaseWeight` 是权重，不是最终百分比，因此不要求所有行为权重之和恒定为 100。

## 2. 性格倍率

沿用原方案：

```text
PersonalityMultiplier =
Clamp(
    1 + Σ(
        Direction
        × (TraitValue - 50) / 50
        × 0.25
    ),
    0.5,
    1.5
)
```

其中：

```text
正向标签 Direction = +1
负向标签 Direction = -1
```

例如：

```text
勇敢       = +1
善良       = +1
-害羞      = -1
```

性格倍率范围：

```text
0.5 ~ 1.5
```

### 性格事件变化建议

普通自主行为不改变性格。

特殊事件修改幅度：

| 事件等级 | 单维性格变化 |
|---|---:|
| 轻微事件 | ±2 |
| 普通重要事件 | ±3 ~ ±4 |
| 关键剧情事件 | ±5 ~ ±8 |
| 单次绝对上限 | ±10 |

最终：

```text
Trait = Clamp(Trait + Delta, 0, 100)
```

避免短时间内将人格完全改变。

## 3. 精力倍率

沿用原公式：

```text
EnergyMultiplier
= 0.6
+ 0.8 × (
    1 - |Energy - PreferredEnergy| / 100
)
```

范围：

```text
0.6 ~ 1.4
```

---

## 4. 精力硬规则补齐

倍率只负责“偏好”，硬规则负责防止不合理行为。

| 当前精力 | 规则 |
|---|---|
| `Energy > 70` | 睡觉不可进入候选池 |
| `30 ~ 70` | 正常参与行为选择 |
| `10 ~ 29` | 正常计算，但不能主动发起高强度特殊交互 |
| `6 ~ 9` | 禁止活跃行为、主动交流 |
| `0 ~ 5` | 未被玩家控制且无强制事件时，强制进入睡觉 |
| `Energy = 0` | 绝不允许继续选择消耗精力的自主行为 |

### 活跃行为定义

当前版本建议标记：

```text
天使：
浇花、门前驻足

恶魔：
打游戏、门前驻足
```

后续新增行为时不要在代码里硬编码名称，使用：

```text
BehaviorTag.Active
```

## 5. 心情分档

```text
0  ~ 29  = LOW
30 ~ 69  = NORMAL
70 ~ 100 = HIGH
```

心情档位只运行时计算，不额外保存。

## 6. 心情倍率表

行为增加 `BehaviorCategory`：

```text
NEUTRAL
REST
QUIET
ACTIVE
SOCIAL
```

对应倍率：

| 行为类型 | 心情差 0~29 | 普通 30~69 | 心情好 70~100 |
|---|---:|---:|---:|
| `NEUTRAL` 中性 | 1.00 | 1.00 | 1.00 |
| `REST` 休息 | 1.40 | 1.00 | 0.70 |
| `QUIET` 安静 | 1.15 | 1.00 | 0.95 |
| `ACTIVE` 活跃 | 0.70 | 1.00 | 1.25 |
| `SOCIAL` 社交/探索 | 0.60 | 1.00 | 1.30 |

设计意图：

- 心情差：更倾向休息、独处、安静行为。
- 心情正常：不修正。
- 心情好：明显提高活跃和社交行为。
- 倍率最大差距控制在约 2 倍以内，避免心情完全覆盖角色性格。

## 8. 行走行为最终定义

“行走”不作为自主行为池中的一个行为。

正确流程：

```text
抽取目标行为
→ 判断行为是否需要移动
→ 如果需要，则进入 Moving
→ 到达行为目标点
→ 执行目标行为
```

因此：

```text
Walking / Moving
```

属于状态机中的中间状态，而不是与“读书 / 浇花 / 打游戏”竞争权重的行为。

行走精力消耗建议按一次移动结算，而不是逐帧结算：

```text
单次普通移动 Energy -1
```

如果路径很短可不扣除；建议仅在移动距离超过一个策划配置阈值时结算。

## 9. 重复倍率

沿用并明确优先级：

| 条件 | RepeatMultiplier |
|---|---:|
| 行为仍处于冷却 | 0 |
| 上一个行为就是该行为 | 0.20 |
| 最近三个行为中出现过 | 0.60 |
| 最近未出现 | 1.00 |

判定优先级：

```text

>
LastAction
>

>
None
```

## 11. 精力自然变化

### 推荐最终值

原表：

```text
醒着每现实 1 分钟 Energy -1
```

如果桌宠动画平均只有几十秒，同时每次行为还会额外扣除 `2~8` 点精力，会导致精力下降过快。

因此推荐改为：

```text
清醒状态每现实 3 分钟 Energy -1
```

睡觉期间停止自然衰减。

最终：

```text
Energy =
Clamp(
    Energy
    - AwakeNaturalDrain
    + ActionEnergyDelta
    + InteractionEnergyDelta,
    0,
    100
)
```

### 如果必须保留“每分钟 -1”

则建议将所有普通行为精力消耗缩小约 50%，否则两套消耗叠加较重。

## 12. 普通行为精力/心情值建议

为了降低状态快速冲顶/清空的概率，推荐对原表做小幅校准：

### 天使

| 行为 | EnergyDelta | MoodDelta |
|---|---:|---:|
| 待机 | 0 | 0 |
| 睡觉 | +25 | +1 |
| 浇花 | -3 | +1 |
| 读书 | -1 | +1 |
| 拉琴 | -2 | +2 |
| 记录 | -1 | +1 |
| 门前驻足 | -4 | 0 |
| 单次普通移动 | -1 | 0 |

### 恶魔

| 行为 | EnergyDelta | MoodDelta |
|---|---:|---:|
| 待机 | 0 | 0 |
| 睡觉 | +25 | +1 |
| 打游戏 | -4 | +2 |
| 画画 | -2 | +2 |
| 门前驻足 | -4 | 0 |
| 单次普通移动 | -1 | 0 |

### 设计目的

- 普通行为消耗控制在 `-1 ~ -4`。
- 睡眠恢复 `+25`，能够明显改变后续行为，但不会一次睡满。
- 普通开心行为以 `+1` 为主。
- 明显喜欢的行为最多 `+2`。
- `+3 ~ +8` 的心情变化留给交流、事件和重要反馈。

## 13. 心情回归中性

沿用：

```text
每现实 5 分钟：
Mood < 50 → +1
Mood > 50 → -1
Mood = 50 → 0
```

最终：

```text
Mood =
Clamp(
    Mood
    + ActionMoodDelta
    + InteractionMoodDelta
    + EventMoodDelta
    + NeutralReturnDelta,
    0,
    100
)
```

### 强烈建议

不要让普通自主行为长期稳定地产生大量正心情。

因此普通行为建议采用上一节校准后的 `+0 ~ +2`，剧情/玩家交互才承担较大的心情波动。

## 14. 亲密度规则

```text
Friendship 范围：0 ~ 100
初始值：30
```

建议关系阶段：

| Friendship | 阶段 |
|---|---|
| 0 ~ 19 | 疏远 |
| 20 ~ 39 | 普通 |
| 40 ~ 59 | 熟悉 |
| 60 ~ 79 | 亲近 |
| 80 ~ 100 | 高亲密 |

当前 `WARM` 阈值继续使用：

```text
Friendship >= 60
```

亲密度不随现实时间自然下降。

## 15. 交流 ResponseType

最终判定：

```text
IF Target.Energy < 30
   OR Target.Mood < 30
    => NEED_SPACE

ELSE IF Friendship >= 60
    => WARM

ELSE
    => NORMAL
```

其中：

```text
NEED_SPACE
```

优先级最高。

---

## 16. 主动交流限制

检查**发起者**：

```text
Initiator.Energy < 10
```

则禁止主动发起交流。

目标对象精力低于 10 时不直接禁止玩家点击，因为玩家仍应得到“对方需要空间”的反馈。

即：

```text
Initiator.Energy < 10
    → 不允许发起

Target.Energy < 30
    → 可以发起，但结果倾向 NEED_SPACE
```

## 17. 交流数值参数表

### 玩家选择“想要交流”并实际触发交流

| ResponseType | 发起者 Energy | 对方 Energy | 发起者 Mood | 对方 Mood | Friendship |
|---|---:|---:|---:|---:|---:|
| `NEED_SPACE` | -1 | -1 | -1 | -1 | 0 |
| `NORMAL` | -2 | -2 | +2 | +2 | +1 |
| `WARM` | -2 | -2 | +3 | +3 | +2 |

### 玩家选择“不打扰了”

```text
EnergyDelta = 0
MoodDelta = 0
FriendshipDelta = 0
```

不惩罚玩家尊重对方状态的选择。

## 18. 防止刷亲密度

为了防止玩家反复靠近、对话快速刷满关系：

```text
FriendshipGainCooldown = 300 秒
```

同一对桌宠在 5 分钟内再次交流：

- 对话仍然可以发生；
- Mood / Energy 正常结算；
- `FriendshipDelta = 0`。

特殊剧情事件不受此限制。

| 事件 | FriendshipDelta |
|---|---:|
| 普通正向事件 | +2 ~ +3 |
| 重要正向事件 | +4 ~ +6 |
| 关键关系事件 | +8 ~ +10 |
| 普通冲突 | -2 ~ -4 |
| 严重冲突 | -5 ~ -8 |
| 剧情决裂 | -10 ~ -20 |

统一：


## 20. 离线时间规则

桌宠属于陪伴型内容，不建议玩家关闭程序后回来发现角色精力直接归零。

推荐：

### Energy

```text
程序关闭期间不进行自然精力衰减。
```

### Mood

允许轻量回归中性：

```text
重新打开时：
根据离线时间向 50 回归
但最多修正 6 点。
```

即最多模拟 30 分钟的心情回归。

例如：

```text
关闭时 Mood = 80
离线 2 小时
重新打开后 Mood = 74
```

而不是直接回到 50。

## 24. 第一版上线后的调参目标

不要追求理论上“绝对平衡”，第一版只需要满足几个可观察指标。

### 行为重复率

目标：

```text
连续两次完全相同行为 < 8%
最近三个行为内重复率 < 25%
```

### 睡觉频率

正常使用下：

```text
不应在 Energy > 70 时睡觉。
低精力后应在较短时间内进入睡觉。
```

### 性格辨识度

观察 30 分钟：

- 天使应明显更常出现读书、记录、浇花、拉琴。
- 恶魔应明显更常出现打游戏、画画。
- 但任何单一行为都不应长期占据绝大多数时间。

建议单个普通行为长期占比：

```text
10% ~ 35%
```

特殊低权重行为：

```text
3% ~ 10%
```

### Mood

普通无事件状态下：

```text
多数时间应位于 35 ~ 80。
```

不应因纯自主行为长期卡在 100。

### Energy

正常陪伴使用下应形成：

```text
清醒活动 → 疲劳 → 休息 → 恢复 → 再次活动
```

而不是：

```text
十几分钟耗尽
```

或：

```text
几小时永远满精力
```

## 25. 最终核心公式

```text
FinalWeight
= BaseWeight
× PersonalityMultiplier
× EnergyMultiplier
× MoodMultiplier
× RepeatMultiplier
```

执行流程：

```text
候选行为生成
→ CurrentState / 玩家控制 / 强制事件过滤
→ Energy 硬规则过滤
→ Cooldown 过滤
→ PersonalityMultiplier
→ EnergyMultiplier
→ MoodMultiplier
→ RepeatMultiplier
→ FinalWeight
→ 归一化加权随机
→ 必要时 Moving
→ 执行动画
→ 结算 Energy / Mood
→ 更新 RecentActions / Cooldown
```

这套方案的重点不是让某个数值单独决定行为，而是让：

```text
角色长期性格
+
当前精力
+
当前心情
+
近期行为历史
```

共同决定桌宠“此刻更可能做什么”，从而让自主行为既有角色差异，又不会完全机械化。
